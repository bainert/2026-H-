# 设计文档：Q3 静态摆球运动序列（中心→+5cm→-5cm）

日期：2026-07-31
状态：已批准

## 背景与目标

赛题第三项（静态摆球控制，13 分）：小车静止时，控制钢球从摆杆中心点 O 向 +5cm 处运行，到达后折返至 -5cm 处并稳定。运行时间 ≤5s，±5cm 处最大误差绝对值 ≤1cm。

当前 `ball.c` 已实现 Q3 闭环摆球：摄像头视觉 → UART0 帧解析（`0xAA data 0x55`）→ `ball_position_mm`（0~250mm，中心 125mm）→ 位置式 PID 输出步进电机脉冲。但目标固定为中心 125mm（`BALL_CENTER_MM`），只支持"球保持中心"。

本设计在现有闭环骨架上增加目标点状态机，实现"中心 → +5cm(175mm) → 折返 → -5cm(75mm) 保持"的自动序列。

## 状态机

| 阶段 | 目标点 (mm) | 触发条件 | 备注 |
|---|---|---|---|
| S0 待命 | 125（中心 O） | 初始 / enter=0 | 目标=中心，与现有行为一致 |
| S1 前往+5 | 175（+5cm） | enter=1 沿触发 | |
| S2 折返-5 | 75（-5cm） | \|pos−175\|≤8mm 持续 300ms | 到达判定见下 |
| S3 完成保持 | 75 | 到达 -5cm | 一直保持，直到 enter=0 回 S0 |

## 关键实现细节

1. **动态目标**：误差 `e = ball_target_mm - pos`，替代原固定 `BALL_CENTER_MM - pos`。目标点由状态机更新。PID 公式、积分限幅（±200）、输出限幅（-213~622 脉冲）、死区（±1mm）全部沿用现有代码。
2. **到达判定**：10ms 周期计数器 `arrive_cnt`，连续 30 次（=300ms）满足 |pos−target|≤8mm 判到达，切换下一阶段。丢帧期间冻结计数，不切换。
3. **切换防冲击**：目标切换瞬间令 `pid_e1 = e`，清零微分项（KD=10.5 下 e 突变 50mm 会产生 ≈525 脉冲的微分冲击，会被限幅打满）。
4. **行程倍率宏**：`BALL_MOVE_KP_GAIN`（默认 1.0，位置式输出 `KP = BALL_KP * BALL_MOVE_KP_GAIN`），实测偏慢时只调此宏，不污染原参数。
5. **丢帧/enter=0**：与现有行为一致——丢帧保持当前角度不更新目标；enter=0 回中心并重置状态机与 PID 状态。
6. **调试显示**：新增全局 `ball_phase`（0=待命 1=去+5 2=去-5 3=保持），OLED Q3 第四行显示 `BAL:` 后追加阶段字符，便于现场观察。

## 改动文件

- `ucdriver/ball/ball.c`：状态机、动态目标、到达判定、防冲击、倍率宏、ball_phase
- `ucdriver/ball/ball.h`：新增 `ball_phase` 声明
- `main.c`：`oled_proc()` Q3 分支显示阶段

不新增文件，不改 build 系统（无需改 sources.mk / makefile）。

## 验收标准

- 实车验证（CCS 编译烧录，无法本地构建）：
  - enter=1 后球从中心出发到达 +5cm 附近，折返后停在 -5cm 附近（误差 ≤1cm）
  - 全程（enter=1 按下到 -5cm 稳定）≤5s
  - enter=0 后球回中心
  - 非 Q3 题号下行为不变（待命）
  - 视觉丢帧时球不失控（保持角度）
- 代码审查：改动仅在 ball.c / ball.h / main.c 三处，无构建系统改动。

## 非目标（YAGNI）

- 不做 B 点/全程带球行驶的摆球与循迹联动（那是 Q4/Q5，后续单独设计）
- 不做目标位置曲线规划（梯形轨迹等），阶跃目标 + 到达判定即可满足 ≤5s
- 不调原有 PID 参数（先实测，必要时只动 `BALL_MOVE_KP_GAIN`）
